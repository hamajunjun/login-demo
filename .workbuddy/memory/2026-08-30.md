# 2026-08-30

## 项目代码评审（login-demo）

用户要求先看项目再给学习建议。评审了 pom.xml、PostServiceImpl、PostLikeServiceImpl、PostFavoriteServiceImpl、UserServiceImpl、PostMapper、PostFavoriteMapper、RedisUtil、WebConfig、RabbitConfig、NotificationListener、application.properties。

### 发现的问题（按优先级）

1. **缓存空值失效 bug**：`RedisUtil.setObject(key, null, ...)` 存的是 JSON 字符串 `"null"`，`getObject` 读出来也是 null，与"缓存不存在"无法区分 → 下次请求仍会加锁查库，空值缓存形同虚设（`getPostById`、`findByUsername` 均受影响）。需要用哨兵值（如 `"NULL"` 字符串）区分。
2. **帖子更新/删除不清缓存**：`updatePost`、`deletePost`、`adminDeletePost` 只改数据库，不删 `post:detail:id` → 修改后最长 30 分钟读到旧数据，删除后帖子仍可从缓存访问。
3. **点赞数 N+1**：`listPosts`、`listByUserId`、`getHotList` 循环调用 `getLikeCount`（每帖一次 COUNT 查询）。应改为 `SELECT post_id, COUNT(*) FROM post_like WHERE post_id IN (...) GROUP BY post_id` 批量查询。（注：收藏列表的 N+1 之前已用 JOIN 修好。）
4. **浏览量写库过频**：`getPostById` 每次阅读都 `increaseViewCount` 写库 + 重写缓存，热点帖 DB 写压力大；可改 Redis INCR + 定时任务批量回写。
5. **注册并发漏洞**：布隆过滤器 + 查库确认不是原子操作，并发同名注册可能都通过；需要 user 表 username 唯一索引兜底。
6. **改名不查重**：`updateCurrentUserInfo` / `updateUserInfo` 不校验新用户名是否已存在。
7. **配置安全**：`application.properties` 中 MySQL 密码为空、`jwt.secret=your-secret-key` 弱默认值、Redis 无密码；应学习配置外部化/环境变量。
8. **JWT 无法注销**：无状态 token 登出只清前端，服务端仍有效；可学 Redis token 黑名单。
